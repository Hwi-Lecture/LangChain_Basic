# 실습: RAG 에이전트

## 실습 목표

노트북에서 살펴본 청킹과 검색 방식을 직접 골라서 문서 검색 에이전트를 구현하고, 에이전트가 문서를 제대로 찾아서 답하는지 확인한 다음 잘못된 부분이 있으면 수정합니다.

## 검색 대상 문서

- 위치: 실습 폴더 기준 `./docs`
- 노트북에서 전처리를 마친 문서들입니다. 전처리는 다시 하지 않아도 됩니다.

| 파일 | 내용 | 형식 |
|---|---|---|
| `01_wafer.txt` ~ `09_packaging.txt` | 반도체 8대 공정 설명 글 9편 (웨이퍼, 산화, IC, 포토, 식각, 증착·이온주입, 금속배선, EDS, 패키징) | txt (제목 구조 없음) |
| `0911(12조간)반도체과, 반도체 첨단패키징 기술강국 도약 시동.md` | 산업통상자원부 첨단패키징 보도자료 (본문 + 첨부 1~3) | 마크다운 (`#`, `##`, `###` 제목 구조 있음) |

## 코드 구조

| 파일 | 내용 | 상태 |
|---|---|---|
| `tools.py` | 문서를 청크로 나누는 `load_chunks`, 검색기를 만드는 `build_retriever`, 에이전트가 사용하는 `search_documents` 도구 | 뼈대만 제공, 1~2단계에서 완성 |
| `app.py` | 에이전트와 streamlit 채팅 화면 | 완성본 제공 |

`app.py`는 에이전트의 답변 아래에 **🔍 문서 검색** 상자를 표시합니다. 상자 제목에는 에이전트가 사용한 검색어가, 상자를 펼치면 `search_documents`가 찾아온 청크가 나옵니다.

## 실습 준비

- `.env`를 `4. RAG/04_RAG_agent` 폴더로 복사하고, 이 폴더를 Visual Studio Code에서 엽니다.
- `.env`에 `Embedding_BASE_URL` 항목이 있는지 확인합니다. 이번 실습은 임베딩 API를 사용합니다.
- 실행 방법과 에러 대응은 01 실습과 같습니다.

## 진행 순서

### 1단계. 청킹 방식 정하고 `load_chunks` 구현

Continue와 함께 `tools.py`의 `load_chunks` 함수를 완성합니다. 이 함수는 `docs` 폴더의 문서를 불러와서 청크로 나눕니다.

**Continue에 요청하기 전에 정리할 내용**

- 보도자료(md)는 어떤 방식으로 나눌까요? 노트북의 청킹 실습에서 정한 방식을 그대로 사용해도 됩니다.
- 8대 공정 txt 문서는 어떻게 할까요? 문서 하나를 통째로 청크 하나로 둘지, 더 작게 나눌지 정합니다. 나눈다면 어떤 방식, 어떤 크기로 나눌지도 정합니다.
- 청크만 따로 떼어서 봐도 어떤 문서의 어떤 부분인지 알 수 있나요? 알기 어렵다면 청크 앞에 어떤 정보(파일명, 제목 등)를 붙일지 정합니다.

나눈 결과를 눈으로 확인할 수 있도록 청크를 `chunks.txt` 파일로도 저장해 달라고 함께 요청합니다.

<summary>10분 이상 진행이 안 되면 펼쳐서 참고하세요</summary>

**참고 프롬프트 (아래 내용을 수정해서 사용하세요):**

`tools.py`의 `load_chunks` 함수를 완성해줘.

- md 파일은 [여러분이 정한 md 청킹 방식]으로 나눠줘.

</details>

`chunks.txt`를 열어서 청크가 의도한 대로 나뉘었는지 확인합니다. 문장이나 표가 중간에 잘린 곳은 없는지, 청크 크기가 너무 들쭉날쭉하지 않은지 봅니다.

**산출물** : `load_chunks`가 구현된 `tools.py`, 청킹 결과 `chunks.txt`

### 2단계. 검색 방식 정하고 `search_documents` 구현

Continue와 함께 `tools.py`의 `build_retriever`와 `search_documents` 함수를 완성합니다.

에이전트는 문서를 직접 볼 수 없습니다. 에이전트가 문서에 대해 아는 정보는 `search_documents` 함수의 설명(docstring)과, 이 도구를 호출해서 받은 청크가 전부입니다. 따라서 검색 방식뿐 아니라 설명에 무엇을 적을지도 함께 정해야 합니다.

**Continue에 요청하기 전에 정리할 내용**

- 어떤 검색 방식을 쓸까요? BM25(키워드), Dense(의미), Hybrid(둘을 섞기) 중 하나를 고르고, Hybrid라면 두 방식의 비중도 정합니다.
- 한 번 검색할 때 청크를 몇 개 가져와서 에이전트에게 넘길까요?
- 에이전트가 언제 이 도구를 써야 하는지 알려면, docstring에 어떤 문서가 들어 있는지를 어떻게 적어야 할까요?
- 3단계에서 검색 결과를 확인할 때, 각 청크가 어느 파일에서 나왔는지 보이면 편합니다. 검색 결과에 파일명을 함께 표시해 달라고 요청합니다.

<summary>10분 이상 진행이 안 되면 펼쳐서 참고하세요</summary>

**참고 프롬프트 (아래 내용을 수정해서 사용하세요):**

### 3단계. 앱 실행해서 확인

터미널에서 아래 명령어로 웹앱을 실행합니다. 앱이 시작될 때 문서를 임베딩하므로 첫 화면이 뜨기까지 시간이 조금 걸립니다.

```
streamlit run app.py
```

아래 질문을 하나씩 입력하고, 답변 아래의 **🔍 문서 검색** 상자를 펼쳐 에이전트가 사용한 검색어와 찾아온 청크를 확인합니다. 답변이 맞아도 필요한 청크를 제대로 찾아왔는지 함께 봅니다.

1. "반도체 첨단패키징 선도 기술개발 사업의 예산과 지원 기간은?"
   * 기준 답변 : 총사업비 약 2,744억 원, 지원 기간은 2025년 ~ 2031년(7년).
2. "첨단전략산업초격차기술개발 사업의 국비 규모와 지원 기간은?"
   * 기준 답변 : 총사업비 약 478억 원 중 국비 394억 원, 지원 기간은 2024년 ~ 2026년(3년). 1번 질문의 사업(2,744억 원)과는 다른 사업임.
3. "칩을 조립하기 전에 불량 칩에 표시를 해서 골라내는 단계는 뭐야?"
   * 기준 답변 : EDS 공정의 Inking 단계. 불량 칩에 특수 잉크를 찍어 표시하고, 잉크가 찍힌 칩은 조립을 진행하지 않음.
4. "EDS 테스트는 몇 단계로 이뤄지고, 각 단계는 뭐야?"
   * 기준 답변 : 5단계.
     1. ET Test & WBI (Electrical Test & Wafer Burn In)
     2. Pre-Laser (Hot/Cold)
     3. Laser Repair & Post Laser
     4. Tape Laminate & Back Grinding
     5. Inking
5. "첨단패키징 MOU에 참여한 10개 기관을 모두 알려줘"
   * 기준 답변 : 자료에 이름이 나오는 기관은 삼성전자, SK하이닉스, LG화학, 하나마이크론, 한미반도체 5곳뿐이고, 나머지 기관은 자료에서 확인할 수 없음.
6. "삼성전자 HBM 수율은 몇 %야?"
   * 기준 답변 : 자료에 포함된 정보가 아님.

### 4단계. 수정하고 다시 확인

3단계에서 기준 답변과 다르게 나온 부분을 수정합니다. 질문마다 원인이 어느 위치에 있는지를 먼저 판단해야 합니다. 에이전트의 답변과 🔍 문서 검색 상자의 내용을 복사해서 continue에게 전달하고 어디가 잘못됐는지 물어봅니다. 잘못 유형은 아래와 같습니다.

1. **필요한 청크를 찾아오지 못한 경우** : 검색 결과에 답이 들어 있는 청크가 없거나, 답의 일부만 들어 있음
2. **청크는 잘 찾아왔지만 답변을 잘못한 경우** : 검색 결과에 답이 들어 있는데 다른 내용과 헷갈리거나, 없는 내용을 지어냄

각 유형에 따라 적절한 곳을 수정해서 에이전트를 보강합니다. 에이전트의 동작을 바꿀 수 있는 곳은 아래 4군데입니다.

| 위치 | 담당하는 부분 |
|---|---|
| `app.py`의 시스템 프롬프트 (`SYSTEM_PROMPT`) | 에이전트가 따르는 태도와 규칙 |
| `tools.py`의 `search_documents` 설명 (docstring) | 에이전트가 이 도구로 무엇을 찾을 수 있는지 |
| `tools.py`의 `load_chunks` 코드 | 문서를 어떤 단위로 나누는지 |
| `tools.py`의 `build_retriever`, `search_documents` 코드 | 어떤 방식으로 몇 개의 청크를 찾아오는지 |

아래 표를 채워 가면서 진행합니다.

| 질문 | 결과 (O/X) | 잘못 유형 (1/2) | 수정 위치 | 수정 후 결과 (O/X) |
|---|---|---|---|---|
| 1 | | | | |
| 2 | | | | |
| 3 | | | | |
| 4 | | | | |
| 5 | | | | |
| 6 | | | | |

수정한 뒤에는 터미널에서 `Ctrl+C`로 앱을 종료하고, `streamlit run app.py`로 다시 실행해서 확인합니다. 브라우저 새로고침만으로는 수정 내용이 반영되지 않습니다. 같은 질문을 입력해서 수정 전 결과와 비교합니다.

> 한 곳을 고치면 다른 질문의 결과가 바뀔 수도 있습니다. 수정한 뒤에는 이미 맞았던 질문도 다시 한번 확인합니다.

## 추가 실습

1. **이어지는 질문** : 1번 질문을 한 다음 "그 사업은 어떻게 구성돼 있어?"처럼 앞 대화를 가리키는 질문을 해 봅니다. 🔍 문서 검색 상자에서 에이전트가 "그 사업"을 어떤 검색어로 바꿔서 검색했는지 확인합니다.

3. **검색 방식 비교** : 2단계에서 고른 검색 방식이나 비중을 바꿔서 3단계 질문을 다시 해 보고, 결과가 어떻게 달라지는지 4단계 표에 이어서 기록합니다.
