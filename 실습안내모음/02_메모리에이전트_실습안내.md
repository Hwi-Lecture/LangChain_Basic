# 실습: 사용자 메모리 관리 에이전트

## 실습 목표

대화 중 나온 정보 중 이후에도 재사용할 가치가 있는 정보를 판단해서 저장하고, 필요할 때 다시 꺼내 쓰는 에이전트를 직접 설계합니다. 구현은 Continue를 통해 진행하고, 이 실습에서 직접 정하는 부분은 "무엇을 기억할지"에 대한 판단 기준입니다.

## 참고 예시

아래는 반도체 DS 부문(에칭 공정 트러블슈팅) 업무를 가정한 예시입니다. 그대로 따라 하는 실습이 아니라, 이후 단계에서 자신의 업무로 바꿔 적용할 때 참고할 형태로 제시합니다.

**페르소나**: 에칭팀 트러블슈팅 메모리 어시스턴트

**대화 예시와 판단**

| 문장 | 기억 여부 | 이유 |
|---|---|---|
| 어제 에칭 공정에서 파티클 이상 발생, 원인은 척(chuck) 오염, 세정으로 해결됨 | O | 이후 유사 이슈 발생 시 재사용 가능 |
| 오늘 점심 뭐 먹지 | X | 일회성 정보 |
| 우리 팀은 웨이퍼를 W, 로트를 L로 줄여씀 | O | 팀 내 컨벤션, 지속적으로 유효 |
| 김OO 선임이 CMP 쪽 전문가라 물어보면 됨 | O | 인물 정보, 지속적으로 유효 |
| 오늘따라 유독 피곤하네요 | X | 업무와 무관한 일시적 정보 |

## 도구 구조

에이전트는 아래 두 가지 도구를 사용합니다.

```python
@tool
def save_memory(content: str) -> str:
    """대화에서 나중에 재사용할 가치가 있는 정보를 저장"""
    ...

@tool
def search_memory(query: str) -> str:
    """저장된 메모리 중 관련 있는 내용을 검색"""
    ...
```

함수 내부 구현(저장 위치, 검색 방식)은 Continue에게 요청해서 채웁니다.

## 실습 준비

- `.env`를 `2. LangChain/01_Memory_Agent` 폴더로 복사하고, 이 폴더를 Visual Studio Code에서 엽니다.
- 실행 방법과 에러 대응은 01 실습과 같습니다.

## 진행 순서

### 1단계. 내 업무 정의

아래 빈칸을 채웁니다.

- 내가 만들 어시스턴트의 역할: [ ]
- 이 어시스턴트와 나눌 법한 대화 문장 5개 (실제 업무 용어로 작성):

  1.
  2.
  3.
  4.
  5.

### 2단계. 분류 워크시트

1단계에서 적은 문장 5개에 대해 표를 작성합니다.

| 문장 | 기억 여부 (O/X) | 이유 |
|---|---|---|
| 문장1 | O | 이유1 |
| 문장2 | X | 이유2 |
| 문장3 | O | 이유3 |
| 문장4 | X | 이유4 |
| 문장5 | O | 이유5 |


### 3단계. tool 작성

Continue에게 다음 내용을 포함해 tool 함수 구현 코드를 요청합니다.

- 메모리는 `memory.md`라는 파일에 기록하고 불러올 수 있도록 합니다.
- `save_memory` 함수의 기능
- `search_memory` 함수의 기능

위 내용을 나의 언어로 정리해서 `save_memory`와 `search_memory`의 구현 코드를 받습니다.
코드는 `tools.py`라는 파일에 구현해 달라고 요청합니다.

**참고 프롬프트 (아래 내용을 수정해서 사용하세요):**
```
langchain 에이전트에 활용할 tool 함수 코드를 구현해줘.

1. `save_memory` : [여러분이 직접 정의한 `save_memory` 함수의 기능]
2. `search_memory` : [여러분이 직접 정의한 `search_memory` 함수의 기능]

메모리는 `memory.md`라는 파일을 생성해서 거기에 기록하도록 구현해줘.
코드는 `tools.py`에 작성해줘.
```

**산출물** : `save_memory`와 `search_memory`가 구현된 `tools.py`

### 4단계. agent 구축

Continue에게 위에서 구현한 tool을 활용하는 에이전트 구축을 아래 내용을 포함해서 요청합니다.

- 시스템 프롬프트 : 언제 `save_memory`를 호출할지, 언제 `search_memory`를 호출할지 기준을 여러분이 직접 지정해서 continue에게 전달합니다.
- tools 리스트에 `save_memory`와 `search_memory`를 포함합니다.

**참고 프롬프트 (아래 내용을 수정해서 사용하세요):**

```
`tools.py`에 있는 tool을 활용하는 챗봇을 구현해줘. 2개의 tool은 아래와 같은 상황에 호출되어야 해.

1. `save_memory` : [여러분이 정한 `save_memory`가 호출되는 시점]
2. `search_memory` : [여러분이 정한 `search_memory`가 호출되는 시점]

위 내용을 시스템 프롬프트에 기록해서 langchain의 `create_agent` 메소드를 이용해서 에이전트를 구축해줘.
llm은 `.env`의 OPENAI_API_KEY와 gpt_4o_mini_BASE_URL을 이용하면 돼. 채팅 ui는 streamlit을 이용해서 구현해줘.
코드는 `app.py`에 작성해줘.
```

### 5단계. tool 호출 표시

`app.py`가 정상적으로 실행되는 것을 먼저 확인한 다음, 에이전트가 tool을 언제 호출하는지 화면에서 볼 수 있도록 기능을 추가합니다.

**참고 프롬프트:**

```
에이전트가 tool을 호출하면 어떤 tool을 어떤 입력으로 호출했는지 채팅 화면에 표시해줘.
```

### 6단계. 테스트

1단계에서 적은 문장 5개를 실제로 입력해, 2단계에서 표시한 기억 여부대로 동작하는지 확인합니다. 다르게 동작하면 시스템 프롬프트를 직접 수정합니다.

1. `save_memory`를 이용해 `memory.md`에 내용을 잘 기록하는지 직접 확인합니다.
2. `memory.md`에 잘 기록되었다면 `search_memory`를 시험해보기 위해 웹을 새로고침하고 다시 채팅해서 관련 내용을 물어봅니다. 잘 구현되었다면 `memory.md`의 내용을 참고해 답변을 할겁니다.

## 추가 과제

위 기능이 모두 정상적으로 동작한다면 아래 과제를 하나씩 진행해 봅니다.

- **메모리 보기** : 사이드바에 현재 `memory.md` 내용을 표시하는 ui를 추가해 봅니다.
- **정보가 바뀌면?** : 이미 저장된 내용과 반대되는 정보를 말해 보고 `memory.md`가 어떻게 되는지 확인합니다. 문제가 있다면 어떻게 해결할지 Continue와 상의해서 개선해 봅니다.
