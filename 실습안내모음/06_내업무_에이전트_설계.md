# 마무리: 내 업무 에이전트 설계하기

## 실습 목표

최종 프로젝트에서 만든 에이전트의 구조를 내 업무에 적용해 봅니다. 코드는 작성하지 않습니다. 회사에 돌아가서 에이전트를 만들거나 요청할 때 쓸 수 있는 **설계서 한 장**을 만드는 것이 목표입니다.

## 예시: 최종 프로젝트의 에이전트

| 항목 | 내용 |
|---|---|
| 업무 | 월간 리뷰 전에 불량률 이상 원인을 조사해서 보고서 초안 작성 |
| 지금 하는 방식 | 공정 데이터를 뽑아서 이상 챔버와 날짜를 찾음 → 설비 이력과 인수인계 메모를 뒤져서 그 시점 기록을 찾음 → 보고서 작성 |
| 필요한 데이터 | 정형: ETCH 공정 Lot 데이터 (DB) / 비정형: 설비 이력, 교대 인수인계 메모 (문서) |
| 도구 | `run_sql` (DB 조회), `search_documents` (문서 검색) |
| 도구 연결 | DB에서 찾은 **설비·챔버·날짜**를 문서 검색어로 넘김 |
| 결과물 | 보고서 초안 (현상, 관련 기록, 추정 원인과 근거, 제외한 원인, 확인 필요 사항) |
| 사람이 확인할 지점 | 추정 원인의 근거 기록이 실제로 있는지, 날짜만 같은 다른 설비의 기록을 원인으로 연결하지 않았는지 |
| 구조로 막을 것 | 자주 쓰는 분석은 정해진 쿼리 도구로, 인용 검사와 조회 순서는 미들웨어로 |

## 진행 순서

### 1단계. 업무 고르기

반복적으로 하는 업무 중 **여러 곳의 정보를 모아서 판단하거나 정리하는 업무** 하나를 고릅니다.

- 예: 주간 보고 작성, 이상 발생 시 원인 조사, 문의 대응, 회의 자료 준비, 기준서·절차서 찾아서 확인하기

### 2단계. 설계서 채우기

아래 표를 참고해서 정리해 봅니다.

| 항목 | 내용 |
|---|---|
| 업무 | |
| 지금 하는 방식 (순서대로) | |
| 필요한 데이터 (정형 / 비정형, 어디에 있는지) | |
| 도구 (이름과 하는 일) | |
| 도구 연결 (앞 도구의 결과 중 무엇을 다음 도구에 넘기는지) | |
| 결과물 | |
| 사람이 확인할 지점 | |
| 구조로 막을 것 (정해진 쿼리 도구, 미들웨어 등) | |

**정리할 때 생각할 내용**

- 필요한 데이터가 표 형태인가요, 글 형태인가요? 표는 SQL 조회, 글은 문서 검색이 어울립니다.
- 에이전트가 틀리면 가장 곤란한 부분은 어디인가요? 그 부분이 "사람이 확인할 지점"입니다.
- 에이전트에게 맡기면 안 되는 일(데이터 수정·삭제, 외부 발송 등)이 있나요?

### 3단계. 아키텍처 그림 그리기

나에게 필요한 에이전트가 어떤 구조를 가질지 그림으로 직접 그려 봅니다. (그림판이나 파워포인트나 편한 툴을 사용하시면 됩니다.) 구조를 글로 쓴 것과 그림으로 그려 보는 것의 이해도 차이는 꽤 큰 편입니다.

<details>
<summary>예시: 최종 프로젝트의 에이전트</summary>

```
[불량률 원인 질문] → [에이전트] → run_sql  → 불량률이 오른 설비·챔버, 시작 날짜
                                  ↓ (넘기는 값 : 설비·챔버·날짜)
                              search_documents  → 그 시점의 설비 이력, 인수인계 메모
                                  ↓
                            [보고서 초안]
```

</details>

### 4단계. 프로토타입 구현해보기

AI를 활용해 실제 사용하는 데이터와 유사한 더미 데이터를 만들어서 에이전트의 기본 틀을 잡아 봅니다. 추가적으로 궁금한 것이 있다면 continue나 강사에게 도움을 요청합니다.
