# 최종 프로젝트: ETCH 이상 원인 보고서 에이전트

## 실습 목표

03 실습의 데이터 조회 도구와 04 실습의 문서 검색 도구를 하나의 에이전트에 연결합니다. 에이전트가 **데이터에서 찾은 결과를 가지고 문서를 검색하고, 두 결과를 이어서 추론하는지** 확인한 다음, 잘못된 부분이 있으면 수정합니다.

## 상황

2026년 8월 ETCH 공정에서 불량률이 상승되는 문제가 발생했습니다. 에이전트를 구축하여 불량률 상승의 원인을 추적해 보고자 합니다.

원인을 찾으려면 두 가지를 함께 봐야 합니다.

- **공정 데이터** : 어느 설비·챔버에서, 언제부터 불량률이 올랐는지 (숫자)
- **현장 기록** : 그 시점에 그 설비·챔버에서 무슨 일이 있었는지 (글)

이번 실습에서는 에이전트가 진짜 원인을 맞히는지보다, **두 정보를 연결해서 추론하는지**에 집중합니다.

## 실습 폴더
* `5. FinalProject/05_final_agent` : 실습 폴더
* `5. FinalProject/시연_구조개선` : 프로젝트 종료 후 시연을 위한 폴더 (프로젝트 진행 시엔 참고하지 않습니다.)

## 사용할 데이터

| 위치 | 내용 | 형식 |
|---|---|---|
| `./db/fab_etch.db` | 03 실습과 같은 ETCH 공정 Lot 데이터 (8월, 11,160건) | SQLite DB |
| `./docs/ETCH_설비이력_202608.csv` | 설비 이력 시스템에서 내려받은 8월 작업 기록 30건 (정기PM, 점검, 알람조치, 변경점) | csv (한 행이 작업 1건) |
| `./docs/ETCH_교대인수인계_202608.txt` | 엔지니어가 교대(주간/오후/야간)마다 남긴 인수인계 메모 8월 한 달치 | txt (`■`로 시작하는 줄이 교대 1회) |

인수인계 메모는 현장에서 쓰는 방식 그대로 약어를 섞어 짧게 적혀 있습니다. 약어와 용어는 `실습안내모음/05_참고_현장용어.md`를 참고하세요.

## 실습 준비

- `.env`를 `5. FinalProject/05_final_agent` 폴더로 복사하고, 이 폴더를 Visual Studio Code에서 엽니다.
- `.env`에 `Embedding_BASE_URL` 항목이 있는지 확인합니다. 문서 검색에 임베딩 API를 사용합니다.
- 실행 방법과 에러 대응은 01 실습과 같습니다.

## 진행 순서

### 1단계. 부품 가져오기

03, 04 실습에서 만든 도구를 이 폴더로 가져옵니다.

1. `3. DataFetch/03_Data_fetch_agent/tools.py`의 내용을 전부 복사해서 `sql_tools.py`에 붙여넣습니다.
2. `4. RAG/04_RAG_agent/tools.py`의 내용을 전부 복사해서 `doc_tools.py`에 붙여넣습니다.

**산출물** : 내용이 채워진 `sql_tools.py`, `doc_tools.py`

### 2단계. 챗봇 완성하기

가져온 부품으로 불량률 상승 원인을 찾는 챗봇을 완성합니다. 무엇을 고치고 무엇을 추가해야 할지는 여러분이 정해서 Continue에게 요청합니다.

**참고사항**

- 에이전트가 DB 조회 도구와 문서 검색 도구를 모두 사용할 수 있는지?
- 두 도구가 이번 폴더의 DB와 문서에서 제대로 동작합니다. 도구의 결과를 직접 확인합니다.

**산출물** : 완성된 `sql_tools.py`, `doc_tools.py`, `app.py`

### 3단계. 앱 실행해서 확인

터미널에서 아래 명령어로 웹앱을 실행합니다. 앱이 시작될 때 문서를 임베딩하므로 첫 화면이 뜨기까지 시간이 조금 걸립니다.

```
streamlit run app.py
```

아래 질문을 하나씩 입력하고, 에이전트가 무엇을 조회하고 무엇으로 검색했는지 확인합니다.

1. "8월 ETCH 불량률 올라간 거 원인 정리해서 보고서 초안 좀 써줘"
   * 이 질문은 아래 체크리스트로 확인합니다.

   | 체크 | 확인 방법 |
   |---|---|
   | ① 데이터에서 이상을 찾았나 | 🗄️ SQL 조회 결과에 불량률이 오른 설비·챔버와 시작 날짜가 나왔는지 |
   | ② 찾은 내용으로 문서를 검색했나 | 📄 문서 검색의 검색어에 ①에서 찾은 설비·챔버·날짜가 들어 있는지 |
   | ③ 연결한 근거를 말했나 | 답변에 "몇 월 며칠 몇 시, 어느 챔버에서 무슨 일이 있었고, 그 직후부터 데이터가 바뀌었다"처럼 시각과 설비·챔버를 맞춰 본 근거가 있는지 |

2. "8월 17일에 ETCH_02 레시피 변경은 관련 없어?"
   * 기준 답변 : 같은 날 있었던 일이지만, 불량률이 오른 설비(ETCH_03)와 다른 설비의 변경이므로 원인으로 보기 어렵다고 판단해야 함. 날짜만 보고 연결하면 틀린 답변.
3. "03B 압력 경고는 언제부터 떴어?"
   * 기준 답변 : 8월 17일 0시 무렵부터 (8월 16일 야간 작업 직후). `03B`가 ETCH_03의 CH_B라는 것을 알고 인수인계 메모를 찾아야 함.

|---|---|---|---|---|
