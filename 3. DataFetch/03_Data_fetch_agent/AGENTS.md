# AGENTS.md — 데이터 분석 에이전트 실습

## 0. 함께 일하는 사람

- 사용자는 **비개발자**입니다. 파이썬과 SQL을 잘 모르며, 코드를 직접 타이핑하지 않고 대화로 실습을 진행합니다.
- 이 실습의 목표는 완성된 앱이 아니라, **사용자가 에이전트의 문제를 직접 발견하고 어디를 고쳐야 하는지 판단하는 연습**입니다.
- 따라서 사용자가 스스로 찾아야 할 문제를 먼저 찾아서 고쳐 주지 않습니다.

## 1. 실습 내용

ETCH 공정 DB(`db/fab_etch.db`, 테이블 `etch_lot`)를 SQL로 조회해서 질문에 답하는 Streamlit 챗봇입니다.

| 파일 | 내용 | 수정 가능 여부 |
|---|---|---|
| `tools.py` | DB를 조회하는 `run_sql` 도구 | 가능 (코드, docstring) |
| `app.py` | 에이전트 생성 + 채팅 화면 | `SYSTEM_PROMPT`만 가능 |
| `db/` | DB 파일과 데이터 사전 | **수정/삭제 금지** |

진행 순서:

1. `tools.py`의 `run_sql` 구현
2. 사용자가 `streamlit run app.py`로 실행해서 질문하고, 🔍 SQL 조회 상자로 쿼리와 결과를 확인
3. 기준 답변과 다른 부분을 사용자가 가져오면, 원인을 진단하고 해당 위치를 수정

## 2. 규칙

### 규칙 1 — 요청한 것만, 한 번에 한 곳만 수정합니다

- 사용자가 요청한 것만 구현하고 멈춥니다. "이왕 하는 김에" 다른 부분까지 고치지 않습니다.
- 사용자가 요청하지 않은 안전장치나 규칙(시스템 프롬프트 규칙 추가, 읽기 전용 설정 등)을 미리 넣지 않습니다. 이것들은 사용자가 3단계에서 문제를 발견하고 요청해야 하는 내용입니다.
- 사용자가 수정 위치를 지정하면 그 위치만 수정합니다.

### 규칙 2 — 수정 전에 원인부터 설명합니다 (3단계)

사용자가 에이전트의 답변이나 SQL 쿼리를 붙여넣고 무엇이 잘못됐는지 물으면, 바로 고치지 말고 아래 순서로 답합니다.

1. **잘못된 유형** : 데이터 조회 자체가 잘못됐는지, 조회는 맞았지만 답변이 잘못됐는지
2. **원인** : 쿼리나 답변의 어느 부분이 왜 문제인지 쉬운 말로 설명
3. **수정 위치 제안** : 아래 세 곳 중 어디를 고치면 되는지와 그 이유

| 위치 | 담당하는 부분 |
|---|---|
| `app.py`의 `SYSTEM_PROMPT` | 에이전트가 따르는 태도와 규칙 |
| `tools.py`의 `run_sql` docstring | 에이전트가 데이터에 대해 아는 정보 |
| `tools.py`의 `run_sql` 코드 | 실제로 실행되는 동작 |

사용자가 동의하면 그때 수정합니다. 수정은 문제 하나에 필요한 만큼만 합니다.

### 규칙 3 — 정해진 범위 밖으로 나가지 않습니다

- 새 파일, 새 도구, 새 라이브러리를 추가하기 전에 먼저 사용자에게 물어봅니다.
- `app.py`의 화면 구성, 함수 구조, 모델 설정(`gpt-4o-mini`, `temperature`)은 바꾸지 않습니다.
- 사용할 라이브러리: `sqlite3`, `pandas`, `langchain`, `langchain_openai`, `streamlit`, `python-dotenv`
- `.env` 파일을 열어서 내용을 출력하지 않고, API 키를 코드에 적지 않습니다.

### 규칙 4 — 결과는 확인해서 보여 줍니다

- `run_sql`을 구현한 뒤에는 간단한 쿼리(예: `SELECT COUNT(*) FROM etch_lot`)로 `run_sql.invoke({"query": ...})`를 직접 실행해 결과를 보여 줍니다. 테스트 코드는 파일에 남기지 않습니다.
- 수정한 뒤에는 "고쳤습니다"로 끝내지 말고, 사용자가 같은 질문으로 다시 확인하도록 안내합니다.
- 에이전트는 실행할 때마다 결과가 달라질 수 있으므로, 같은 질문을 2~3번 확인해 보도록 안내합니다.

### 규칙 5 — 비개발자가 이해할 수 있게 설명합니다

- 코드를 수정한 뒤에는 무엇을 왜 바꿨는지 2~3문장으로 설명합니다.
- SQL 쿼리를 설명할 때는 "어떤 데이터를 어떤 기준으로 계산하는 쿼리인지"를 말로 풀어서 설명합니다.
- 전문 용어는 처음 나올 때 쉬운 말로 풀어 줍니다.
- 사용자가 "이게 무슨 뜻이야?"라고 물으면 코드를 고치지 말고 설명만 합니다.

## 3. 자주 막히는 지점

- **수정했는데 결과가 그대로일 때** : `app.py`는 에이전트를 `@st.cache_resource`로 한 번만 만들어 둡니다. 그래서 `SYSTEM_PROMPT`나 `tools.py`를 수정한 뒤 브라우저를 새로고침해도 이전 에이전트가 그대로 사용됩니다. 터미널에서 `Ctrl+C`로 앱을 종료하고 `streamlit run app.py`로 다시 실행하도록 안내합니다.
- **DB 파일을 찾지 못할 때** : 터미널의 현재 위치가 이 실습 폴더인지 확인합니다. `DB_PATH`는 실행 위치 기준 상대경로입니다.
- **조회 결과가 너무 많을 때** : `MAX_ROWS`(100행)를 넘는 결과는 앞부분만 돌려주도록 `run_sql` 코드에서 처리합니다.
